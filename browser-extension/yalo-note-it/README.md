# Yalo note it — Browser Extension

这是 Yalo note it 的 AI Web 入口，当前支持 ChatGPT Web 与 DeepSeek Web。只有点击插件中的“Yalo note it”按钮才会运行；平时不监听网页文字，也不执行后台轮询。

当前版本：**0.12.7**。

扩展图标使用 `icons/` 中的 16、32、48 和 128px PNG；可编辑的品牌母版位于 `brand/yalo-mark.svg`。

## 安装

需要 Chrome 102+，或采用同代及以上 Chromium 内核的 Edge。

1. 在 Chrome 打开 `chrome://extensions`；Edge 打开 `edge://extensions`。
2. 开启“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择本目录：`browser-extension/yalo-note-it`。
5. 建议将扩展固定到浏览器工具栏。

## 使用

### 首次设置

先在 Codex 中安装并配置 Yalo note it Skill。Codex 会创建实际归档根目录 `YaloNote`，并在其中写入 `.yalo-note-location.json`。这个文件保存根目录的绝对路径，供浏览器扩展构造当前会话的 `file:///` 地址。

点击插件中的“设置本地目录”，选择 Codex 已初始化的 `YaloNote` 文件夹，或直接包含它的父目录。历史归档根名称 `yalo note` 和 `yalo-note` 也可以直接选择。插件会验证目录读写能力和 Codex 写入的路径描述文件，通过后才保存目录句柄。插件不创建归档根目录，也不迁移归档内容。

如需更改实际路径，必须先在 Codex 中执行路径配置，并明确选择迁移旧内容或保留旧内容；完成后再在插件中重新选择新根目录。不要只在插件中改变目录，否则 Codex 与浏览器会指向不同位置。

目录设置分为四步：

1. 浏览器返回所选目录的文件系统句柄，插件定位其中已由 Codex 初始化的归档根；
2. 插件请求归档根的 `readwrite` 权限；
3. 插件创建、写入并删除临时测试文件，同时校验 `.yalo-note-location.json`；
4. 全部成功后，插件才把归档根句柄保存到扩展自己的 IndexedDB。

成功提示必须是“目录已验证并保存”。只选中目录或保存了目录句柄，不代表插件已经取得写权限。验证失败时不会保留本次无效设置。

### 导出 Raw Record

1. 打开目标 ChatGPT 或 DeepSeek 对话。
2. 点击扩展图标，再点击“Yalo note it”。ChatGPT 页面里的消息文字不会触发插件。
3. 扩展会从顶部向下读取虚拟化加载的消息，按消息 ID 去重，并保留角色、标题、段落、列表、链接、表格、代码块和附件名称。
4. 在 ChatGPT 中，扫描经过用户上传的文件卡时，扩展会立即尝试通过当前仍有效的下载入口取得文件。DeepSeek 当前只记录上传文件名，不下载附件二进制。
5. 角标显示 `OK` 后，记录包位于 `<Codex 归档根>\sessions\<chatgpt|deepseek>\<conversation-id>\`：
   - `conversation.raw-record.md`：按顺序保存的网页对话原始记录；
   - `manifest.json`：文件保存状态、来源消息、原名、大小和 SHA-256；
   - `assets\`：成功取得的用户上传文件。
6. Raw Record 是原始记录，不做总结、润色或观点合并。

若文件入口已经过期、页面不再提供下载或文件超过 25 MB，记录任务仍会保存对话，并在 `manifest.json` 中把该文件标为 `unavailable` 或 `too_large`。插件不会把失败的文件标成已保存。

点击按钮后保持插件窗口打开。插件从稳定顶部开始加载和读取消息，并在窗口中显示最终成功信息或具体错误。写入完成或失败后，任务状态会在 `finally` 阶段释放；失败时可按错误提示处理后再次点击。

记录失败后，当前标签页会保留红色 `ERR` 和对应的具体错误；即使关闭再打开弹窗，状态区仍会优先显示该错误。重新开始记录、记录成功、切换到其他会话或关闭标签页后，旧错误会被清除；同一会话内只有查询参数或锚点变化时不会误清除。

“停止当前任务”只在扫描阶段生效，停止后不会写入不完整档案，也不会留下 `ERR`。进入文件写入阶段后，为避免产生半写入档案，插件会拒绝停止并提示等待完成。

### 打开当前会话归档

设置过本地目录后，在已有稳定会话 ID 的 ChatGPT 或 DeepSeek 对话页打开扩展，点击左下角的“打开当前归档”。扩展会根据当前标签页 URL 定位 `sessions/<provider>/<conversation-id>/`，校验 `manifest.json` 的来源身份，再读取 `.yalo-note-location.json` 中的绝对路径，通过 `file:///` 在 Chrome 新标签页打开该会话目录。

此操作只读取现有文件，不创建目录、不补写归档，也不会把其他会话的记录当成当前会话。如果目录、`manifest.json` 或 Raw Record 不存在，弹窗会明确提示当前会话尚无归档。该标签页是 Chrome 的本地文件目录页，不是 Windows 资源管理器，也不是扩展内部的 Raw Record 阅读器。

使用前还必须打开 `chrome://extensions`，进入 **Yalo note it** 的“详细信息”，开启“允许访问文件网址”。未开启时，扩展会拒绝打开并显示具体提示。

## 升级与重新加载

这是以“加载已解压的扩展程序”方式安装的本地扩展。代码更新后，浏览器不会自动采用新版本：

1. 打开 `chrome://extensions` 或 `edge://extensions`；
2. 找到 **Yalo note it**；
3. 点击扩展卡片上的刷新按钮，或点击页面顶部“更新”；
4. 确认版本号为 **0.12.7**；
5. 重新打开目标对话页面和插件弹窗。

## 目录权限故障

### “记录目录权限已失效”

这个状态表示插件还保存着目录句柄，但浏览器当前没有向该句柄授予写权限。常见于扩展被重新加载或浏览器重新启动。直接点击“Yalo note it”即可在采集页面前完成重新授权和真实写入测试，无需重新选择目录。

处理方法：

1. 确认扩展已经更新到 0.12.7；
2. 点击“Yalo note it”；
3. 接受浏览器对已保存记录目录的访问请求。

只有目录被移动、删除或句柄彻底失效时，才需要点击“设置本地记录目录”重新选择。

### 浏览器提示不能使用系统文件夹

Chrome/Edge 会阻止扩展访问磁盘根目录和部分敏感系统位置。不要选择磁盘根目录、用户主目录、下载目录入口或文件选择器侧栏项目。请先在 Codex 中把归档路径配置到普通本地目录，再通过插件选中 Codex 创建的 `YaloNote` 或其父目录。插件不会自行创建归档根。

### “无法写入所选目录”

插件已经取得或尝试取得浏览器授权，但实际的测试文件写入失败。弹窗会附带底层文件系统错误。检查目录是否仍然存在、是否只读、是否被安全软件拦截，以及当前 Windows 用户是否拥有修改权限，然后重新设置目录。

## 页面适配器架构

扩展分为两层：

- `service-worker.js`：通用采集引擎，负责滚动、等待、去重、排序、进度、停止和文件写入；
- `providers/*.js`：站点适配器，负责域名、会话 URL、页面节点、消息角色和正文提取。

当前提供 ChatGPT 适配器 `providers/chatgpt.js` 和 DeepSeek 适配器 `providers/deepseek.js`。未注册的网页会明确提示“当前网页尚未配置 Yalo note it 页面适配器”。适配器契约见 [`providers/README.md`](providers/README.md)。

## 限制

- ChatGPT 或 DeepSeek 页面结构变化后，滚动区域或消息节点识别规则可能需要更新。
- 单次任务最多扫描 2000 个滚动步，以防页面异常时无限运行。
- 只保存用户上传到当前对话的文件；不追溯助手历史生成文件、Canvas 内容或其他会话中的文件。
- ChatGPT 文件必须在执行记录时仍能通过页面下载；DeepSeek 当前只记录附件名称。
- 单个文件保存上限为 25 MB。
