# Yalo note it — Browser Extension

这是 Yalo note it 的 ChatGPT Web 入口。只有点击插件中的“Yalo note it”按钮才会运行；平时不监听网页文字，也不执行后台轮询。

当前版本：**0.10.1**。

扩展图标使用 `icons/` 中的 16、32、48 和 128px PNG；可编辑的品牌母版位于 `../brand/yalo-mark.svg`。

## 安装

1. 在 Chrome 打开 `chrome://extensions`；Edge 打开 `edge://extensions`。
2. 开启“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择本目录：`skills/yalo-note-it/assets/browser-extension`。
5. 建议将扩展固定到浏览器工具栏。

## 使用

### 首次设置

点击插件中的“设置本地记录目录”，选择一个明确的本地父目录并授予写权限。插件会在其中创建固定的 `yalo note` 子目录，并在子目录内创建、写入和删除临时测试文件；只有测试通过后才保存目录设置。本工具不提供默认路径。浏览器安全模型不允许扩展在未经选择授权的情况下直接写任意位置；此步骤通常只需一次。

以后重新选择父目录时，插件会询问是否把原有内容全部迁移到新路径。选择迁移时，插件先复制并校验内容，再清理旧目录；选择不迁移时，旧内容保留在原路径，新记录写入新路径。

目录设置分为四步：

1. 浏览器返回所选目录的文件系统句柄；
2. 插件请求该目录的 `readwrite` 权限；
3. 插件在目录中创建、写入并删除临时测试文件；
4. 全部成功后，插件才把目录句柄保存到扩展自己的 IndexedDB。

成功提示必须是“目录已验证并保存”。只选中目录或保存了目录句柄，不代表插件已经取得写权限。验证失败时不会保留本次无效设置。

### 导出 Raw Record

1. 打开目标 ChatGPT 对话。
2. 点击扩展图标，再点击“Yalo note it”。ChatGPT 页面里的消息文字不会触发插件。
3. 扩展会从顶部向下读取虚拟化加载的消息，按消息 ID 去重，并保留角色、标题、段落、列表、链接、表格、代码块和附件名称。
4. 扫描经过用户上传的文件卡时，扩展会立即尝试通过 ChatGPT 当前仍有效的下载入口取得文件。建议先把最终采用的文件重新上传到当前对话，并用一条消息说明它是最终版本。
5. 角标显示 `OK` 后，记录包位于 `<所选父目录>\yalo note\sessions\chatgpt\<conversation-id>\`：
   - `conversation.raw-record.md`：按顺序保存的网页对话原始记录；
   - `manifest.json`：文件保存状态、来源消息、原名、大小和 SHA-256；
   - `assets\`：成功取得的用户上传文件。
6. Raw Record 是原始记录，不做总结、润色或观点合并。

若文件入口已经过期、页面不再提供下载或文件超过 25 MB，记录任务仍会保存对话，并在 `manifest.json` 中把该文件标为 `unavailable` 或 `too_large`。插件不会把失败的文件标成已保存。

点击按钮后保持插件窗口打开。插件从稳定顶部开始加载和读取消息，并在窗口中显示最终成功信息或具体错误。写入完成或失败后，任务状态会在 `finally` 阶段释放；失败时可按错误提示处理后再次点击。

## 升级与重新加载

这是以“加载已解压的扩展程序”方式安装的本地扩展。代码更新后，浏览器不会自动采用新版本：

1. 打开 `chrome://extensions` 或 `edge://extensions`；
2. 找到 **Yalo note it**；
3. 点击扩展卡片上的刷新按钮，或点击页面顶部“更新”；
4. 确认版本号为 **0.10.1**；
5. 重新打开 ChatGPT 页面和插件弹窗。

## 目录权限故障

### “记录目录权限已失效”

这个状态表示插件还保存着目录句柄，但浏览器当前没有向该句柄授予写权限。常见于扩展被重新加载或浏览器重新启动。直接点击“Yalo note it”即可在采集页面前完成重新授权和真实写入测试，无需重新选择目录。

处理方法：

1. 确认扩展已经更新到 0.10.1；
2. 点击“Yalo note it”；
3. 接受浏览器对已保存 `yalo note` 目录的访问请求。

只有目录被移动、删除或句柄彻底失效时，才需要点击“设置本地记录目录”重新选择。

### 浏览器提示不能使用系统文件夹

Chrome/Edge 会阻止扩展访问磁盘根目录和部分敏感系统位置。不要选择磁盘根目录、用户主目录、下载目录入口或文件选择器侧栏项目。请先在资源管理器中创建一个普通父目录，再通过目录选择器选中它；插件会在其中创建 `yalo note` 子目录。

### “无法写入所选目录”

插件已经取得或尝试取得浏览器授权，但实际的测试文件写入失败。弹窗会附带底层文件系统错误。检查目录是否仍然存在、是否只读、是否被安全软件拦截，以及当前 Windows 用户是否拥有修改权限，然后重新设置目录。

## 页面适配器架构

扩展分为两层：

- `service-worker.js`：通用采集引擎，负责滚动、等待、去重、排序、进度、停止和文件写入；
- `providers/*.js`：站点适配器，负责域名、会话 URL、页面节点、消息角色和正文提取。

当前只提供 ChatGPT 适配器 `providers/chatgpt.js`，所以 0.9.0 的实际支持范围仍然是 ChatGPT Web。未注册的网页会明确提示“当前网页尚未配置 Yalo note it 页面适配器”。适配器契约见 [`providers/README.md`](providers/README.md)。

## 0.9.0 变更

- 在 Raw Record 之外生成结构化 `manifest.json`；
- 保存用户重新上传到当前 ChatGPT 对话且下载入口仍有效的文件；
- 文件写入 `assets\`，重名时生成不冲突的本地文件名；
- 保存文件大小、MIME 类型和 SHA-256；
- 下载失败或超过 25 MB 时保留明确状态，不伪造成功结果。

## 0.10.0 变更

- 不再提供默认记录路径，首次设置必须由用户明确选择本地父目录；
- 在所选父目录下创建固定的 `yalo note` 子目录；
- 更改路径时询问是否迁移原有内容，迁移前检查同名冲突并在复制校验成功后清理旧目录；
- 选择不迁移时保留旧内容，仅把后续记录写入新目录。

## 0.10.1 变更

- 每次点击 `Yalo note it` 后，先检查目录句柄、恢复读写授权并执行临时文件写入测试；
- 只有预检全部通过后才开始滚动和采集页面，避免完成长对话扫描后才发现无法写入。

## 0.9.1 变更

- 扩展重新加载或浏览器重启后，点击“Yalo note it”会对已保存目录重新请求写权限；
- 保留有效目录句柄，不再把临时权限丢失误导为必须重新设置目录。

## 0.8.0 变更

- 将 ChatGPT 域名、会话 ID 和 DOM 提取规则移入独立页面适配器；
- 通用采集引擎不再包含 ChatGPT 专属选择器和错误判断；
- 记录目录由适配器 ID 决定，ChatGPT 仍写入 `sessions/chatgpt/`；
- 为未来站点适配建立明确接口，但未声明或暗示支持未经验证的站点。

## 0.7.3 变更

- 修复目录句柄已保存、实际写权限未授予时仍显示设置成功的问题；
- 设置目录时明确请求 `readwrite` 权限；
- 通过临时文件执行真实写入验证，成功后才保存配置；
- 所选目录验证失败时清理无效配置；
- 插件弹窗启动时检查已保存目录的当前写权限；
- 为权限拒绝和真实写入失败提供不同错误信息。

## 限制

- ChatGPT 页面结构变化后，滚动区域或“展开”按钮识别规则可能需要更新。
- 单次任务最多扫描 2000 个滚动步，以防页面异常时无限运行。
- 只保存用户上传到当前对话的文件；不追溯助手历史生成文件、Canvas 内容或其他会话中的文件。
- 文件必须在执行记录时仍能通过 ChatGPT 页面下载。
- 单个文件保存上限为 25 MB。
